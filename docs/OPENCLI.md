# OpenCLI 接入策略

OpenCLI 只用于登录态下、由用户主动触发的小红书调研。工作台不绕过验证码，不维护批量抓取循环，也不调用自动发布、关注或取关命令。

## 本地准备

项目已固定 `@jackwener/opencli` 版本。使用 Codex 工作区 Node.js 20+ 运行：

```powershell
pnpm opencli:doctor
```

首次使用仍需按照 OpenCLI 官方文档安装 Browser Bridge，并在浏览器中正常登录小红书。

## 数据流

1. 用户选择漫画，并创建包含 2–3 个关键词的 `research_tasks`。
2. 用户点击“本机执行”，OpenCLI 复用同一个临时浏览器会话逐个打开搜索页。
3. 每次都重新检查页面控件，再点击“图文 / 一周内 / 未看过 / 最多点赞”。
4. 只读取每个关键词的初始可视结果，不滚动；跨关键词按 URL 去重并最多保留 10 条。
5. 用户在导入箱预览、选择和确认。
6. 通过审核的项目写入 `references`，并关联所属漫画；搜索阶段先保存标题等列表字段，详情采集作为下一阶段 Workflow。

## 默认安全边界

- 每批 2–3 个关键词，去重后最多展示 10 条。
- 每个关键词不自动滚动加载更多。
- 不提供定时轮询。
- 不自动下载全部媒体。
- 不自动发布和互动。
- 保存来源链接、采集时间和原始响应。
- 登录墙、验证码、访问异常、筛选项缺失或页面变化时立即停止，不自动重试。
