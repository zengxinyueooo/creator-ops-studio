# 任务执行报告

保留 `agent_run_events` 作为逐条事实日志；新增 `agent_run_reports`，每个 `run_id` 一条 JSONB 报告。报告包含概况、时间线、工具耗时与恢复结果、最终产物。报告不保存原始模型会话、隐藏推理、图片或凭证。

## 页面查看

调研页参考笔记卡片下点击“查看执行日志”，选择最近 100 次采集中的一次，可刷新并导出完整 JSON。页面对所选任务分页读取全部事件后汇总，不受原进度接口最近 50 条的限制。当前视图从事实实时汇总，不依赖报告表，因此也可查看尚未结束和历史任务。未实际记录的步骤无法补全；不是所有工作流都有采集级工具审计。

## 部署

在 Supabase 执行 `supabase/migrations/202609110001_agent_run_reports.sql` 后重启 Worker。报告按用户隔离，只允许用户读取自己的报告；客户端不能写报告。

Worker 在任务结束时生成一份报告，保存失败只告警，不改变业务结果。进程被强制终止时 finally 无法执行，需要人工补生成；当前没有自动补偿调度。

补生成或重建某一次报告：

```powershell
node --import tsx agent/rebuildReports.ts <run_id>
```

报告从原始事件和任务当前结果重新计算，不编造历史缺失信息。页面展示的是刷新时的状态；执行中可手动刷新。迁移部署前，页面汇总可用，但报告副本不能写入新表。
